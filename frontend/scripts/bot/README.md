# Risktionary load-test bots

Bots that join a running game over HTTP and WebSocket (STOMP) and play as
guessers. They exist to test that the backend keeps up under load, in
particular how quickly AI feedback is generated and delivered.

> **Note:** this bot was generated by Claude (Anthropic) by exploring the
> frontend codebase to work out the join flow, STOMP destinations and event
> shapes. It is a testing tool, not part of the product. If the backend
> contract changes, the bot may need updating (the type imports from `src/`
> will make `npm run typecheck` flag most changes).

## Requirements

- Node 22.18+ (runs the TypeScript directly via built-in type stripping, no
  build step). Developed against Node 24.
- A running backend, and a game that has been created but not yet started.

## Usage

A human host must create the game in the UI (creating a game needs OAuth login,
which the bots can't do). Then, with the game code:

```
npm run bot -- --code ABC123 --bots 20
```

Start the game from the host UI once the bots have joined. Press Ctrl+C to
stop; a final summary is printed.

## Options

| Option             | Default                        | Description                                                        |
| ------------------ | ------------------------------ | ------------------------------------------------------------------ |
| `--code`           | (required)                     | Game code to join                                                  |
| `--bots`           | `10`                           | Number of bots                                                     |
| `--api`            | `http://localhost:8080`        | Backend HTTP base URL                                              |
| `--ws`             | `ws://localhost:8080/ws`       | Backend WebSocket URL                                              |
| `--prefix`         | (none)                         | Optional display name prefix (`<prefix>-Emma`)                     |
| `--guess-interval` | `8000`                         | Ms between each bot's guesses, randomised +-50%                    |
| `--ramp`           | `200`                          | Ms between each bot joining                                        |
| `--guesses`        | a few risk terms               | Comma-separated guess pool                                         |
| `--volunteers`     | `0`                            | The first N bots volunteer to draw                                 |
| `--report`         | `15`                           | Seconds between summaries                                          |

## What each bot does

1. `POST /v1/game/join` with the game code and a unique random first name (e.g. `Emma`; `Emma2` once the
   built-in list of 50 names is used up).
2. Connects to the WebSocket with `?ticket=`, subscribes to the same
   destinations as the frontend, then sends `/app/player/ready`.
3. Follows the round phase from `STATE`, `PHASE_STATE` and `ASSIGNED_*` events.
4. **DRAWING:** guessers send guesses to `/app/game/chat` at a randomised rate.
   A bot that is picked as drawer sends a 1x1 PNG snapshot every 10 seconds.
5. **RANKING:** sends one random risk rating per round.
6. Records the time from its own guess echoing back in chat to the matching
   `FEEDBACK` event arriving.

## Output

Every `--report` seconds, and on exit:

```
[stats] joined=20 failed=0 connErr=0 disc=0 | guesses=143 echoes=143 fb(msg)=120 fb(round)=15 noFbYet=23 | latency ms p50=4200 p95=9100 max=12000
```

- `joined` / `failed`: successful and failed joins
- `connErr` / `disc`: STOMP errors and websocket closes
- `guesses`: guesses sent; `echoes`: own messages seen back in chat
- `fb(msg)`: feedback attached to a message; `fb(round)`: round-level feedback
- `noFbYet`: echoes minus message feedback received. Includes feedback still in
  flight, so it is an upper bound on failed or timed-out generations
- `latency`: guess echo to feedback arrival

## Limitations

- Bots can't know the real word, so most guesses are incorrect. To exercise the
  correct-guess path, put the game's actual words in `--guesses`.
- The snapshot is a 1x1 image, enough to hit the endpoint but not to give the AI
  anything meaningful to work with.
- Bots can't create or start a game.
- Keep the code to erasable TypeScript syntax (no enums or parameter
  properties), since Node only strips types.
