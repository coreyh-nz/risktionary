# Risktionary Backend

A Spring Boot backend application for Risktionary, built with Kotlin.

---

## Getting Started

### Development

Run the app locally with automatic recompilation on code changes.

```bash
./gradlew bootRun
```

The app runs at http://localhost:8080

### Production (Docker)

Build and run the app in a Docker container.

1. Build the image
    ```bash
    docker build -t backend .
    ```

2. Run the container
    ```bash
    docker run -p 8080:8080 backend
    ```

   To run in detached mode (background):
    ```bash
    docker run -p 8080:8080 -d backend
    ```

The app runs at http://localhost:8080

### Docker Compose

Builds the image and starts the container in one step. Useful for running alongside other services.

```bash
docker compose up --build
```

To run in detached mode (background):

```bash
docker compose up --build -d
```

The app runs at http://localhost:8080

## Environment Variables

### Required

The following environment variables are mandatory for handling OAuth authentication and issuing JWTs.

| Variable                | Description                                               |
|-------------------------|-----------------------------------------------------------|
| JWT_SECRET              | Secret key used for signing and verifying JSON Web Tokens |
| GOOGLE_CLIENT_ID        | OAuth 2.0 Client ID for Google login                      |
| GOOGLE_CLIENT_SECRET    | OAuth 2.0 Client Secret for Google login                  |
| MICROSOFT_CLIENT_ID     | OAuth 2.0 Client ID for Microsoft login                   |
| MICROSOFT_CLIENT_SECRET | OAuth 2.0 Client Secret for Microsoft login               |
| MICROSOFT_TENANT_ID     | Microsoft Entra ID (Tenant ID) for Microsoft login        |

### Profiles

The backend uses different configurations depending on the active Spring profile.

- **postgres** - connects to an external PostgreSQL instance
- **h2** - uses an in‑memory H2 database (no environment variables required)

#### Postgres Profile

When running with the `postgres` profile, the following environment variables **must** be set:

| Variable          | Description                    |
|-------------------|--------------------------------|
| DATABASE_NAME     | Name of the MariaDB database   |
| DATABASE_USER     | Username for the database      |
| DATABASE_PASSWORD | Password for the database user |

#### H2 Profile

When running with the `h2` profile, the application uses an in‑memory H2 database.
No environment variables are required.

## Configuring AI

AI feedback is built from three **use cases**. Each one runs on its own **provider** and **model**, so
they can be mixed freely, for example screenshots analysed by a hosted model and text generated by a
local one.

| Use case               | What it does                                             | Needs a vision model |
|------------------------|----------------------------------------------------------|----------------------|
| `image-analysis`       | Interprets drawing screenshots                           | Yes                  |
| `fact-generation`      | Writes the neutral fact note from a player's guesses     | No                   |
| `fact-framing-rewrite` | Rewrites the fact note in the player's assigned framing  | No                   |

Every provider must speak the **OpenAI chat completions API**. OpenAI, Gemini, OpenRouter and Ollama all
do, so no extra dependency is needed to switch between them.

### Quick start (OpenAI only)

Set an API key and a model for each use case. Everything else has a default.

| Variable                                       | Description                                         |
|------------------------------------------------|-----------------------------------------------------|
| OPENAI_API_KEY                                 | API key for the `openai` provider                   |
| FEEDBACK_AI_USE_CASE_IMAGE_ANALYSIS_MODEL      | Model that analyses drawings (must support images)  |
| FEEDBACK_AI_USE_CASE_FACT_GENERATION_MODEL     | Model that generates fact notes                     |
| FEEDBACK_AI_USE_CASE_FACT_FRAMING_REWRITE_MODEL | Model that rewrites fact notes in a framing        |

Optional:

| Variable                                             | Default | Description                              |
|------------------------------------------------------|---------|------------------------------------------|
| OPENAI_BASE_URL                                      | `https://api.openai.com/v1` | Point the `openai` provider elsewhere |
| FEEDBACK_AI_USE_CASE_IMAGE_ANALYSIS_TEMPERATURE      | `0.2`   | Sampling temperature                     |
| FEEDBACK_AI_USE_CASE_FACT_GENERATION_TEMPERATURE     | `0.3`   | Sampling temperature                     |
| FEEDBACK_AI_USE_CASE_FACT_FRAMING_REWRITE_TEMPERATURE | `0.4`  | Sampling temperature                     |

### Choosing a provider for a use case

Each use case picks a provider by name with a `..._PROVIDER` variable. It defaults to `openai`.

| Variable                                          | Default  |
|---------------------------------------------------|----------|
| FEEDBACK_AI_USE_CASE_IMAGE_ANALYSIS_PROVIDER      | `openai` |
| FEEDBACK_AI_USE_CASE_FACT_GENERATION_PROVIDER     | `openai` |
| FEEDBACK_AI_USE_CASE_FACT_FRAMING_REWRITE_PROVIDER | `openai` |

These providers are built in:

| Provider     | Base URL                                                     | API key variable     |
|--------------|--------------------------------------------------------------|----------------------|
| `openai`     | `https://api.openai.com/v1` (or `OPENAI_BASE_URL`)           | OPENAI_API_KEY       |
| `gemini`     | `https://generativelanguage.googleapis.com/v1beta/openai/`   | GEMINI_API_KEY       |
| `openrouter` | `https://openrouter.ai/api/v1`                               | OPENROUTER_API_KEY   |
| `local`      | `http://localhost:11434/v1` (Ollama, or `LOCAL_AI_BASE_URL`) | LOCAL_AI_API_KEY (defaults to `ollama`) |

Model names are whatever the provider expects: for example `vendor/model` on OpenRouter, or a tag such as
`name:tag` on Ollama.

**Example: screenshots on Gemini, text on a local Ollama model**

```bash
GEMINI_API_KEY=...
FEEDBACK_AI_USE_CASE_IMAGE_ANALYSIS_PROVIDER=gemini
FEEDBACK_AI_USE_CASE_IMAGE_ANALYSIS_MODEL=<a Gemini model that accepts images>

FEEDBACK_AI_USE_CASE_FACT_GENERATION_PROVIDER=local
FEEDBACK_AI_USE_CASE_FACT_GENERATION_MODEL=<an Ollama model tag>
FEEDBACK_AI_USE_CASE_FACT_FRAMING_REWRITE_PROVIDER=local
FEEDBACK_AI_USE_CASE_FACT_FRAMING_REWRITE_MODEL=<an Ollama model tag>
```

Only providers that a use case actually uses need credentials. Changing a provider or model needs a
restart.

### Adding or customising a provider

Providers live under `app.ai.providers` in `application.yaml`. Add an entry to introduce a new
OpenAI-compatible endpoint, then reference its name from a use case.

```yaml
app:
  ai:
    providers:
      my-provider:
        base-url: https://example.com/v1        # include the version path
        api-key: ${MY_PROVIDER_API_KEY:}
        timeout: 60s                            # per request, default 60s
        max-retries: 2                          # default 2
        headers:                                # optional extra headers on every request
          X-Title: risktionary
```

| Setting       | Default                     | Description                                             |
|---------------|-----------------------------|---------------------------------------------------------|
| `base-url`    | `https://api.openai.com/v1` | API base URL, **including its version path**            |
| `api-key`     | none, required if used      | API key. Providers that need none still need a placeholder value |
| `timeout`     | `60s`                       | How long one request may take                           |
| `max-retries` | `2`                         | How many times a failed request is retried              |
| `headers`     | none                        | Extra headers sent with every request                   |

The application fails at startup, with a message naming the use case, if a use case refers to a provider
that is not configured or that has no API key.

### Things to know

- **Vision.** `image-analysis` sends screenshots, so its model must accept images. Text-only models
  cannot be used for it.
- **Speed.** Before a round is saved the game waits for outstanding AI calls, up to
  `app.game.persistence.pending-ai-timeout` (default `10s`). Slow models, such as a local one on modest
  hardware, may need this raised, and a slow provider needs a matching `timeout`. Calls still running
  after the wait are abandoned and counted on the round.
- **Prompts.** The prompts under `src/main/resources/ai/prompts` were written and tuned against OpenAI
  models. Smaller models can follow rules such as "never reveal the answer" less reliably, so check the
  output after switching.
- **Token usage.** Usage is recorded for every AI call, along with its provider and model. Some
  providers report no token counts, and those calls are recorded as zero.
- **Research data.** Each game records the provider, model and temperature every use case ran with
  (`risktionary_game_ai_use_case`), so results can be compared across models later.
- **Tests.** No API keys or network access are needed. The test configuration replaces every model with a
  mock.
